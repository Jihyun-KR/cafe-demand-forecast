# 내일 몇 잔 팔릴까 — 날씨 기반 카페 수요 예측

> "내일 비가 오면 아이스 아메리카노가 얼마나 덜 팔릴까?"
> 매장에서 매일 감으로 하던 발주를, 날씨와 요일 데이터로 조금 더 정확하게 해보자는 프로젝트입니다.

## 왜 만들었나

바리스타 자격증을 준비하며 커피를 직접 내려보니, 한 잔이 제때 나오려면 재료가 미리 준비되어 있어야 했습니다.
그런데 매장 발주는 보통 "지난주 이맘때쯤 이만큼 나갔으니까" 같은 감에 기대는 경우가 많습니다.
날씨처럼 매일 바뀌는 요인을 반영하면 재고 낭비와 품절을 함께 줄일 수 있지 않을까 싶어 만들어봤습니다.

## 결과 한눈에

| | 모델 | 기존 방식(최근 4주 같은 요일 평균) |
|---|---|---|
| 5개 메뉴 하루 평균 오차 합계 | **46.3잔** | 73.6잔 |
| 오차 감소 | **37.1%** | |

- 메뉴별로는 **아이스 아메리카노**의 개선 폭이 가장 컸습니다 (오차율 27.2% → 10.5%). 기온 변화에 가장 민감한 메뉴라, 요일 평균만으로는 날씨가 확 바뀌는 날을 따라가지 못했기 때문입니다.
- 평일 기준 **기온 약 8°C**를 넘으면 아이스 아메리카노가 따뜻한 아메리카노보다 많이 팔린다고 예측했습니다.
- 블렌디드 음료는 기온보다 **주말·공휴일 여부**가 훨씬 중요한 요인이었습니다.

## 대시보드에서 할 수 있는 것

1. **내일 판매 시뮬레이터** — 요일, 기온, 비 여부를 바꾸면 메뉴별 예상 판매량이 바로 바뀝니다.
2. **발주 메모** — 예상 판매량으로 원두, 우유, 아이스·핫 컵 수량을 계산해줍니다 (여유분 10%).
3. **성능 검증** — 숨겨둔 마지막 90일 동안 실제 판매, 모델 예측, 기존 방식을 비교합니다.
4. **요인 분석** — 메뉴마다 기온, 강수량, 요일, 주말·공휴일 중 무엇이 판매를 움직였는지 보여줍니다.

## 방법

- **데이터**: 오피스 상권 카페 1곳을 가정한 2년치(2024–2025) 일별 판매 샘플 데이터 5개 메뉴 × 731일
- **피처**: 기온, 강수량, 요일, 주말·공휴일 여부
- **모델**: 메뉴별 `HistGradientBoostingRegressor` (scikit-learn)
- **검증**: 시간 순서를 지켜 마지막 90일을 테스트로 분리 (미래 데이터가 학습에 섞이지 않게)
- **비교 기준**: 현장에서 흔히 쓰는 "최근 4주 같은 요일 평균"
- **중요도**: 퍼뮤테이션 중요도 (요인 하나를 뒤섞었을 때 예측이 얼마나 나빠지는지)

## 설계하면서 고민한 점

- **왜 정확도보다 '기존 방식 대비 개선'을 먼저 보여주나**: 매장 입장에서 궁금한 건 "지금 하는 방식보다 나은가"입니다. 그래서 비교 기준을 현장의 실제 발주 습관으로 잡았습니다.
- **왜 결과를 '잔 수'와 '준비물'로 보여주나**: 예측 숫자만으로는 바로 행동하기 어렵습니다. 원두 몇 kg, 컵 몇 개처럼 바로 준비할 수 있는 단위로 바꿔야 실제로 쓰인다고 생각했습니다.
- **왜 랜덤 분할이 아니라 시간 순서로 나눴나**: 랜덤으로 섞으면 미래 날짜의 데이터로 과거를 맞히는 셈이 되어 성능이 실제보다 좋게 나옵니다.

## 한계와 다음 단계

- 판매·날씨 모두 **합성 샘플 데이터**입니다. 숫자보다 "흐름을 읽는 방법"을 보여주는 데 목적이 있습니다.
- 트리 기반 모델이라 학습 데이터에 없던 극단적인 기온(한파, 폭염)에서는 예측이 평평해집니다.
- 다음에는 실제 기상청 데이터 연결, 상권 유형·프로모션·기념일 피처 추가, 매장별 모델 분리를 해보고 싶습니다.

## 실행 방법

```bash
pip install -r requirements.txt
python src/generate_data.py   # 샘플 데이터 만들기 → data/cafe_sales_sample.csv
python src/train.py           # 학습·평가 → dashboard/index.html 생성
```

`dashboard/index.html`을 브라우저로 열면 대시보드를 볼 수 있습니다.

### 실제 기상청 날씨로 바꾸기

기상자료개방포털(data.kma.go.kr)에서 서울(108) ASOS 일자료 CSV를 내려받은 뒤,
`src/weather.py`의 `load_kma_asos()`로 읽어 날씨 부분을 교체하면 됩니다.
